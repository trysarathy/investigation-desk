## Description (as written by the author)

Closes `team/SECURITY_GAPS.md` row 1 (High).

**Problem.** `POST /api/demo/reset` has no demo-mode check. One POST with no body on a live server
replaces Files A/B with the demo files and deletes `cases.json` and `bulk/`.

**Fix.**
- `src/app/api/demo/reset/route.ts`: return 403 unless `isDemoMode()` (the same switch the rest of the
  app uses, so `DEMO_MODE=off|0|false|no|live` are all live). Nothing is written or deleted.
- `src/components/DemoPanel.tsx`: the Settings → Data "Load/Reset demo workspace" button used to fail
  silently on any error; it now shows the route's message (`role="alert"`).
- Behaviour change, on purpose: a live server can no longer load the demo workspace over the
  customer's files. Demo servers are unchanged.

Not in this PR: the CSRF check (gap #2) is separate.

**Acceptance criteria**
1. With `DEMO_MODE=off` (and its synonyms) the route returns 403 and `cases.json`, `bulk/` and
   `workspace.json` are untouched.
2. In demo mode the reset still works exactly as before.
3. The panel shows the reason when the reset is refused.

**Tests.** `tests/demo-reset-guard.test.ts` (new, 7 tests: 1 + 5 synonyms + demo mode still works).
`npx tsc --noEmit` 0, `npx vitest run` 569 passed / 57 skipped, `npx next build` OK.

**Demo/real-mode check.** Unit tests on a temp `DESK_DATA_DIR` for both modes.
