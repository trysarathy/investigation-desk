## Description (as written by the author)

Closes `team/SECURITY_GAPS.md` row 7 (Low).

**Problem.** `csvCell` only checks the first character against `= + - @ \t \r`. Full-width `＝ ＋ － ＠`,
or a zero-width space / BOM in front of `=`, get through, and a cell holding `;` isn't quoted, so a
`;`-splitting spreadsheet can start a new cell with `=1+1`.

**Fix.** `src/lib/csv/cell.ts`: the prefix check runs on a copy with leading zero-width space/BOM
stripped and NFKC applied (which folds the full-width signs to ASCII). The cell itself is written
unchanged, with the `'` prefix when needed. `;` joins the characters that force quoting.

**Acceptance criteria**
1. Each look-alike start (＝ ＋ － ＠, ZWSP+`=`, BOM+`=`) is neutralised.
2. A cell containing `;` is quoted.
3. Ordinary text is unchanged; existing CSV/export tests pass.

**Tests.** `tests/csv-cell-fullwidth.test.ts` (new, 7 tests). **All 7 fail on `main` and pass with the
fix** (I checked). `npx tsc --noEmit` 0, `npx vitest run` 569 passed / 57 skipped.

**Demo/real-mode check.** Exported `/api/payments/export.csv` in demo mode; file opens normally.
