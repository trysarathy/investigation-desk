## 1. Xero granular scopes
Apps created on or after 2 March 2026 get granular scopes only, so `DEFAULT_SCOPES` no longer asks for `accounting.transactions`. New default:

`openid profile email offline_access accounting.invoices accounting.payments accounting.banktransactions accounting.contacts.read`

| Endpoint in `providers/xero.ts` | Scope | Source |
|---|---|---|
| `GET /Invoices` | `accounting.invoices` | Xero dev blog, Apideck |
| `PUT /CreditNotes` | `accounting.invoices` (credit notes sit under invoices) | Xero dev blog, Apideck |
| `PUT /CreditNotes/{id}/Allocations` | `accounting.invoices` | [ASSUMPTION]: neither source names allocations |
| `PUT /Invoices/{id}/History` | `accounting.invoices` | [ASSUMPTION]: neither source names history |
| `PUT /Payments` | `accounting.payments` | Xero dev blog, Apideck |
| `PUT /BankTransactions` (RECEIVE-OVERPAYMENT) | `accounting.banktransactions` | Xero dev blog, Apideck |
| Contact IDs on invoices | `accounting.contacts.read` | Apideck (contacts scope unchanged) |

There's no separate `accounting.invoices.read`, because writing credit notes needs write on `accounting.invoices`, which already includes reading. `XERO_SCOPES` still overrides the default, for older apps on broad scopes (they have until September 2027). Sources: https://devblog.xero.com/upcoming-changes-to-xero-accounting-api-scopes-705c5a9621a0 and https://apideck.com/blog/xero-scopes. The comment in `xero-auth.ts` and `docs/ACCOUNTING_SYNC.md` are updated to match.

## 2. Approval requires the plan key
`expectedKey` is now required in `approveAndPost` (engine) and `approvePosting` (service). Before, a missing or empty key skipped the check and posted whatever the current plan was. Now that case is refused, and the refusal goes into the audit log as "Not posted: Plan key missing…". The UI route already required a string key, and an empty string is now refused too. Demo seeding approves using each plan's own key.
