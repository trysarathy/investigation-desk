# Clearline v1: decisions log

Decisions taken during the v1 build that the founder's instructions did not cover. Each one takes the most
conservative option: it never loosens matching, weakens security, costs money or touches legal text. Every entry says
how to reverse it. Founder decisions themselves are recorded in `PROGRESS_V1.md` and the PR descriptions, not here.

| # | Date | Area | Decision | Why | How to reverse |
|---|---|---|---|---|---|
| 1 | 2026-11-25 | CI | Every browser spec waits for a non-empty `<title>` before running axe, not only the one that flaked. | With `retries: 0` the same streamed-title gap could fail any axe check after a client-side navigation. | Remove the `waitForFunction(... document.title ...)` lines in `tests/browser/*.spec.ts`. |
| 2 | 2026-11-25 | Docs | #115's five rc5 docs are kept as history (`docs/history/rc5/`, `docs/security/THREAT_MODEL_V0_RC5.md`); ADR 0004 goes into `docs/adr/` as it is still accurate. | Fold in what is useful without presenting rc5 plans as current. | Delete those files. |
| 3 | 2026-11-25 | FX (A2) | A recorded fiat rate values an amount only if it was recorded at most 24 h before the instant it values; a rate "as of" more than 5 minutes ahead of the recording clock is refused. [ASSUMPTION, for sign-off] | Never value with a stale or future-dated rate; otherwise "needs a rate". | Change `FIAT_RATE_MAX_AGE_MS` (`src/lib/clearline/merchant/fx.ts`) and `FUTURE_SLACK_MS` (`src/server/merchant-setup.ts`). |
| 4 | 2026-11-25 | FX (A2) | Two sources disagreeing at the same instant make the value "needs a rate"; the engine never chooses between them. `fiat_rates` is append-only (a correction is a new instant or source). | Choosing a source is an accounting decision. | Add a source-priority rule (approval-only). |
| 5 | 2026-11-25 | FX (A2) | Other-currency batches tie in their own currency; a payment or bank line in another currency naming the batch is an exception (`M5.batch.currency_mismatch`), never converted to tie. | Converting to tie would loosen matching. | None proposed (would loosen matching). |
| 6 | 2026-11-25 | FX (A2) | Period-end revaluation is only PROPOSED, for provider clearing only (the ledger revalues the bank itself [ASSUMPTION]); FX posting rules are a DRAFT pending sign-off; nothing is posted. | Posting is approval-only. | Build the posting rules after sign-off. |
| 7 | 2026-11-25 | Uploads (A2) | The bank account is part of a statement line's fingerprint, so the same line in two accounts is two lines and again in the same account a duplicate. | Never merge lines of different accounts. | Drop the account from the fingerprint (`src/server/normalise.ts`). |
| 8 | 2026-11-25 | Token-priced (A3) | A token-priced invoice's fiat value is "needs a rate" everywhere (never 0) unless a recorded rate at most 24 h old exists [ASSUMPTION, for sign-off]. | A 0 would read as a real value. | Change `TOKEN_PRICE_RATE_MAX_AGE_MS` (`src/lib/clearline/merchant/match.ts`). |
| 9 | 2026-11-25 | Accounting (A3) | IAS 21 realised FX at settlement for token-priced invoices is documented as a DRAFT only (not built, nothing posted). | Accounting standard points need an accountant's sign-off. | Build after sign-off. |
| 10 | 2026-11-25 | Matching (A3, #174) | Refund rows in a per-payment file are an approval-only draft: a refund row never links its payment to a batch and never closes an order by amount; an order with one is never closed by decision 1 or the token rule. | Refunds must not loosen matching. | Remove the `refund` line type (0046). |
| 11 | 2026-11-25 | Database (A3) | chain_reads partitions are created 24 months ahead (0047). | Room for a missed maintenance run. | Change `CHAIN_READ_PARTITION_MONTHS_AHEAD` (`src/server/chain-read-partitions.ts`) and the migration. |
| 12 | 2026-11-25 | Deployment (A3, #165) | A production server refuses to start without `CLEARLINE_DEPLOY_ENV`. | A deployment must say where it runs. | Remove the check in `src/server/deploy-guard.ts` (security, approval-only). |
| 13 | 2026-11-25 | Onboarding (B1) | Invitations expire after 72 h [ASSUMPTION] (the database caps any at 7 days); the token travels only in the link's `#fragment`; invite-only, every sign-up path is a 404. | Shortest workable window; tokens never reach server logs. | Change `INVITATION_HOURS`. |
| 14 | 2026-11-25 | Onboarding (B1) | The platform console and setup wizard write only through `clearline_provisioning` (EXECUTE on `prov_*` functions, no table privilege); without `DATABASE_PROVISIONING_URL` setup is unavailable. | Least privilege. | Point the wizard at another login (not recommended). |
| 15 | 2026-11-25 | Login (B2) | TOTP is required for Admin and Approver; a TOTP code is accepted once; never "trust this device"; reset only to a verified address and it revokes every session; attempt limits are database-backed and keyed on the trusted client address only. Passkeys use a hand-written WebAuthn verifier (APPROVAL-ONLY review). OIDC SSO is not built (no new packages). | Strengthens security without new dependencies. | Each is a setting in `src/server/auth*.ts` (security, approval-only). |
| 16 | 2026-11-25 | Access (B3) | A membership scoped to no entity sees nothing (fail closed); organisation-wide changes (provider grant, retention, access review, other entities' policies) need an unscoped membership; rows without an entity are hidden from a scoped member, except `fx_rates` (org-wide rates). | Scoping only tightens. | Drop the RESTRICTIVE policies (0053; security, approval-only). |
| 17 | 2026-11-25 | Matching (A1) | Bank evidence is a separate level (none / imported_two_person_confirmed / bank_authenticated reserved, nothing sets it); a batch is settled only when it ties to the cent with evidence ≥ imported_two_person_confirmed; an exact payment whose settlement is only a proposed grouping is matched with "settlement not linked", never settled. | Founder decisions 12–16; the amount-only and preparer rules are unchanged. | Deactivate `M5.batch.tied_evidence_separate` / `M5.grouping.matched_settlement_unlinked` in `rules.ts`. |
| 18 | 2026-11-25 | FX (integration) | `fx_rates` (token→fiat quotes, since 0006) and `fiat_rates` (fiat→fiat cross rates, 0044) are kept separate on purpose. | Different sources, keys and meaning; one table would blur which rate valued what. | Merge them in a migration (not recommended). |
| 19 | 2026-11-25 | Email (integration) | One EmailSender, `send({to, subject, text, html?, kind?})`; the only stand-in is the `email_outbox` table (web app insert-only); B1's folder outbox is removed. Unconfigured: invitations refuse, other mail is dropped. | Keeps both agents' behaviours; no message without its invitation, no arbitrary mail. | Revert 0068 and the sender in `src/server/email`. |
