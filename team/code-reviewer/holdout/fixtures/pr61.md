## Description (as written by the author)

Fixes roadmap item 1, `bug/xero-posting-date-timezone`.

**Problem.** Posting lines take their date from `blockTime.slice(0, 10)`, which is the UTC day. A
payment that lands at 01:30 SGT on 1 Nov is posted to Xero (and QuickBooks) on 31 Oct, in the
wrong day and sometimes the wrong month.

**Fix.** New helper `orgDay()` in `src/lib/format.ts` returns the calendar day in the organisation's
timezone, and `planPosting` uses it for every line's date. Both Xero and QuickBooks read `line.date`,
so both are fixed by the one change.

**Acceptance criteria**
1. A payment at 2026-10-31T17:30Z (01:30 SGT, 1 Nov) posts with date 2026-11-01.
2. A payment in the SGT afternoon keeps its day.
3. Existing posting tests still pass.

**Tests.** `tests/posting-date.test.ts` (new, 3 tests). The first one fails on `main` and passes
with the fix. `npx tsc --noEmit` 0, `npx vitest run` 565 passed / 57 skipped.

**Demo/real-mode check.** Demo books only (no live Xero org yet).
