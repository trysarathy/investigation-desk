# Clearline Control — database schema (rc5)

- **Engine:** PostgreSQL 16 (tested on 16.15 locally; `postgres:16` in CI).
- **Schema source:** `src/server/db/schema.ts` (Drizzle ORM 0.45.4).
- **Migrations** (applied with `npx drizzle-kit migrate` as the owner):
  - `drizzle/0000_init.sql`, generated by drizzle-kit;
  - `drizzle/0001_security.sql`, written by hand;
  - `0002_import_confirmation.sql` (generated) and `0003_evidence_provenance_immutable.sql` (hand-written): two-person statement imports, immutable evidence provenance;
  - `0004_hardening_tables.sql` (generated) and `0005_hardening_security.sql` (hand-written): `login_failures`, staged-lines hash, triggers bound to the signed-in user, TEMP revoked, `pg_temp`-last definer functions, narrower grants, immutable payment identity.

## Roles

| Role | Login | Attributes | Used by |
|---|---|---|---|
| `clearline_owner` | yes | owns the schema, `BYPASSRLS`, `CREATEROLE` | migrations, `scripts/control/admin.ts`, tests' reset — **never the web app** |
| `clearline_app` | no | `NOBYPASSRLS`; holds the grants | group role |
| `clearline_runtime` | yes | member of `clearline_app`, `NOBYPASSRLS`, owns nothing | the web app (`DATABASE_URL`) |

The grants follow least privilege:
- **Tenant record tables:** SELECT, INSERT and UPDATE, and no DELETE anywhere — except: no INSERT on `payment_intents`, no INSERT/UPDATE on `provider_events`, no UPDATE on `idempotency_records` (0005). A payment's identity and amount cannot change (trigger), nor can evidence provenance (trigger).
- **`audit_events`, `investigation_notes`, `approval_decisions`:** INSERT and SELECT only.
- **Memberships and organisations:** SELECT only.
- **Auth tables:** what Better Auth needs, including DELETE on `sessions` and `verifications`.

## Row-level security

- **Scope.** Every tenant table has `ENABLE` and `FORCE ROW LEVEL SECURITY` with the policy below.
  - `app_org_id()` reads the transaction-local setting.
  - `app_is_member()` is SECURITY DEFINER and checks an active membership of `app_user_id()`.
- **Without a context, nothing is visible.**
  - With no context set, the runtime role sees 0 rows (tested).
  - With another organisation's id forced into the context, it also sees 0 rows, because membership is required (tested).

```sql
USING (org_id = app_org_id() AND app_is_member(org_id)) WITH CHECK (same)
```

- **`organization_memberships`:** a user sees their own memberships, and the members of the organisation in context.
- **`organizations`:** a user sees the organisations they belong to.

## Money

- **Engine side.** All amounts are integer minor units: JavaScript safe integers in the engine (≤ 10^15, checked) and `bigint` in PostgreSQL.
  - Decimals per currency come from `src/lib/clearline/money.ts`: SGD/USD/EUR/PHP 2, USDC 6.
  - Every product or ratio is computed in BigInt.
- **No float in either layer.** Neither layer uses floating point anywhere money is stored or computed.

## Backup and retention (design; local procedure tested by hand only)

- **Backup:** `pg_dump --format=custom` of the database as the owner, encrypted at rest by the operator.
- **Retention:**
  - audit, approvals and evidence: kept for the life of the organisation (append-only);
  - idempotency records: may be pruned after 30 days by the owner;
  - sessions: expire after 8 h; expired rows may be pruned.
- **Restore:** `pg_restore` into an empty database created by `scripts/db/setup-local.sh`, then `drizzle-kit migrate` (a no-op if current). The runbook is in `docs/runbooks/DEPLOYMENT_RUNBOOK_RC5.md`.
- **Not done:** a hosted backup schedule, which needs hosted infrastructure and therefore founder approval.
