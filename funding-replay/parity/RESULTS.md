## How to read this

- **same**: both engines give the same normalised answer. **differs**: they do not; every difference is reviewed in `docs/PARITY_REVIEW.md` (code vs fixture vs policy vs wording). **n/a**: one side is not available, not expressible in that engine's schema, or the engine raised an error.

- Rebuild usable cash is derived as required + headroom (or read from the cash check text when required is unknown); the rebuild has no per-option usable field.

- Known: the set of common fact ids visible to each engine at the as-of, restricted to facts both translators emit with the same known_at (translation-only records such as the rebuild's calendar/floor, and facts the translations date differently, are excluded and listed per scenario).

- XL-FLOOR: cash_floor SGD 0 added. The original has no cash-floor policy; the rebuild requires one (missing -> cash unknown).
- commitment_list: original reservation_snapshot (amount 1) -> rebuild commitment_list status complete, same times.
- delivery_bound: one per-route original record per slot -> rebuild service_bound with no slot and no expiry (rebuild reads it as common to both slots).
- fee: one fact -> two rebuild fee records (rail 20 + processing 15/25), same times.
- funding_rate: not a record in the rebuild; passed to evaluate() as funding_rate_pct = 8.
- invoice: -> obligation (effective_at = spendable deadline) + release_checkpoint.
- reservation: original reserved_sgd (an earmark inside the gross balance, active on [effective, valid_until)) -> rebuild commitment with EMPTY effective_at, so it is always subtracted. With an effective_at at or before the balance time the rebuild would treat it as already paid out of the balance and not deduct it. The active window is not expressible (rebuild commitments have no expiry).
- slot: funding_slot merges the instruction time (original: code constant, known from the start) and the cutoff (original: cutoff_sgt record first known 14:00 on the day). known_at = the slot fact's schedule_known (Thu 12 09:00 unless the scenario says otherwise), so the rebuild learns the Monday cutoff earlier than the original's record. The strict alternative is the probe_monday_slot_unknown_friday scenario.
