## Description (as written by the author)

Closes `team/SECURITY_GAPS.md` row 3 (Medium).

**Problem.** With `PREVIEW_USER`/`PREVIEW_PASSWORD` set, the middleware lets `/pay/*` through but not
the payer's look-alike-address checker `POST /api/pay/<publicId>/check`, which returns 401. So in the
recommended pilot set-up the poisoning warning silently stops working.

**Fix.** `src/middleware.ts` also lets the payment-page API through, like the page itself. Both carry
their own unguessable link ID.

**Acceptance criteria**
1. `POST /api/pay/<publicId>/check` is reachable without the preview password.
2. Everything else under `/api`, and every page, still needs the password.

**Tests.** `tests/preview-gate.test.ts` (new, 3 tests). The first fails on `main` (401) and passes
with the fix; the other two guard the rest of the API and the pages.
`npx tsc --noEmit` 0, `npx vitest run` 565 passed / 57 skipped.

**Demo/real-mode check.** `PREVIEW_USER=u PREVIEW_PASSWORD=p npx next dev`, then
`curl -X POST localhost:3400/api/pay/x/check -d '{"address":"0x00…"}'` → 404 (reached the route), no 401.
